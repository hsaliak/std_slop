Agent runtime

Invocation, state, and review are explicit.

The application is a C++17 CLI with interactive and batch modes. It persists conversation and tool state in SQLite, loads project instructions and skills, and sends assembled context to the configured provider.

Invocation examples

Interactive, batch, JSON, and schema-constrained output.

Interactive

$ std_slop

> inspect the build graph
> /session switch refactor
> /context show

Interactive mode keeps the session ledger and exposes slash commands for sessions, context, messages, skills, and model selection.

One prompt

$ std_slop --prompt \
    "Summarize the repository structure"

Batch mode accepts one instruction source. Optional piped stdin is prepended as context.

Run metadata

$ std_slop --prompt_file task.md \
    --output=json | jq -r .assistant_message

--output=json emits run metadata including status, session, model, active skills, assistant message, structured output, errors, and duration.

Structured value

$ std_slop --prompt "Extract the name" \
  --format '{"type":"object","properties":{"name":{"type":"string"}},"required":["name"],"additionalProperties":false}'

The validated JSON value is the only stdout payload. It cannot be combined with --output=json.

File-driven batch execution

Use a schema file for automation.

The prompt, schema, model, session, and database can be selected independently. This keeps structured output usable from shell scripts and CI jobs.

incident-summary
$ cat incident.log | std_slop \
    --prompt_file summarize_incident.md \
    --format_file incident_summary.schema.json \
    --model gpt-5.4-mini:high \
    --session incident-2026-07-19 \
    --prompt_db /tmp/slop-incident.db

Persistent state

The database is part of the runtime contract.

01

Messages and tools

Interaction groups, tool calls, statuses, parsing strategy, and token counts are stored in the ledger.

02

Sessions

History and context settings are isolated by session_id. Active skills and process-level throttling are preserved when switching.

03

Skills and project context

AGENTS.md, SKILL.md, and configured specializations contribute explicit prompt material at the agent boundary.

04

Context management

Accordion history preserves complete recent groups and resets at a configured prompt watermark. The state summary remains in the conversation history.

Mail Mode

Clean, bisect-safe changesets.

Mail Mode treats the agent as a reviewable contributor. The workflow prioritizes manual code review and keeps finalization separate from implementation.

  1. Create or switch to slop/staging/*.
  2. Make one logical change and commit an atomic patch.
  3. Run deterministic verification for every commit.
  4. Review the series and request rerolls with review comments.
  5. Finalize only the approved staging HEAD.
